# 会话汇总修复回归验证

日期：2026-10-21（Asia/Shanghai）
测试规则提交：`d95e9bbd7392bc29fd050b09af9a0be393af7491`。

**三组、六个教学回合的目标检查通过：补建时沿用未结束的会话；已有新会话不回退；明确开始新会话时记录划分依据。旧汇总均标为历史并指向学习档案，后续作答没有造成新的当前计数冲突。**

## 测试方法

- 三组为不继承父聊天历史的独立 Codex GPT 会话（`fork_turns=none`），未覆盖模型；精确模型及客户端版本未单独采集。每组两轮在同一执行会话内继续，每个场景执行一次。
- 使用已安装的 skill 和记录规则；测试前后均核对其与仓库及测试基线哈希一致，见 [skill-baseline.json](skill-baseline.json)。
- 执行会话只收到技能路径、自身隔离学习目录和合成用户输入，未提供检查项、预期输出或其他组结果。只允许读写自身目录中的学习数据，不允许读取真实学习档案。
- 所有背景、目标、原题、原答、历史日期、编号和后续用户补答均为合成测试输入。测试组织者只准备 initial、冻结逐轮快照和保存真实回复，未手工修正教学输出。
- A 从原问题的缺主档初始资料开始；B 从原问题已经产生冲突的最终资料开始，仅把其中“当前学习目录”改为自身隔离路径；C 从原档案齐全资料开始，并由用户明确要求新开会话。原问题证据保留在上一轮测试中。
- 输入和预先定义的检查项见 [test-plan.json](test-plan.json)；初始哈希见 [initial-hashes.json](initial-hashes.json)。机械检查见 [verification.json](verification.json)，独立只读复核见 [review-note.md](review-note.md)。

## 范围与限制

本次验证的是显式提供技能路径、已知目录及合成资料时的行为，没有验证桌面自动加载、跨平台安装、多个写入会话并发、全部缺档组合或长期可靠率。不存在“每次都一定通过”的统计结论。

规则还说明了编号缺号、证据不足时待核对及过期主档按最新事件恢复；本次没有分别构造这些边界场景，不将它们列为已完成行为测试。未用真实学生档案作为测试数据；目录访问约束不等于操作系统层面的隔离验证。
